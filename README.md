# Lumina — GCP RAG Assistant

> An AI Engineering portfolio project that implements a **Retrieval-Augmented Generation (RAG)** pipeline to answer technical questions over official Google Cloud Platform (GCP) documentation.

---

## 📖 Overview

Lumina is an end-to-end AI assistant built for GCP engineers. Instead of relying on generic knowledge, Lumina scrapes the latest GCP documentation, processes it, and uses semantic search to provide highly accurate, context-aware answers. 

This project demonstrates core AI Engineering skills, including:
- Asynchronous web scraping
- Advanced document chunking strategies
- Local vector embeddings
- Vector database indexing
- LLM orchestration

---

## 🏗️ Architecture

The system is broken down into two distinct pipelines: **Background Ingestion** and **Real-Time RAG**.

```
User
  ↓
Frontend (React)
  ↓
FastAPI (POST /ask)
  ↓
Real-Time RAG Pipeline
├── Retriever → ChromaDB (semantic search)
│       ↓
│   Top-K chunks + metadata
│       ↓
└── Generator → Groq/Llama (LLM response)

Background Ingestion Pipeline (--setup flag)
├── Scraping   → crawl4ai → Local File System (data/raw/)
├── Chunking   → LangChain MarkdownHeaderTextSplitter
├── Embedding  → sentence-transformers/all-MiniLM-L6-v2
└── Indexing   → ChromaDB (chroma_db/)
```

### The Data Flow Explained
1. **Scraping**: `crawl4ai` asynchronously crawls 24 specific GCP AI/ML documentation pages, converting them to clean Markdown and saving them locally.
2. **Chunking**: The Markdown files are split using a `MarkdownHeaderTextSplitter` to preserve semantic meaning based on headers, followed by a `RecursiveCharacterTextSplitter` for large sections.
3. **Embedding & Indexing**: The chunks are converted into vectors using a local HuggingFace model (`all-MiniLM-L6-v2`) and stored in **ChromaDB**.
4. **Retrieval**: When a user asks a question, the question is embedded, and ChromaDB is queried for the top 5 most relevant document chunks.
5. **Generation**: The retrieved chunks are injected into a prompt alongside the user's question and sent to `llama-3.3-70b-versatile` (via Groq API) to generate a precise answer.

## 🛠️ Tech Stack

| Component | Technology | Why we chose this |
|---|---|---|
| **Scraping** | `crawl4ai` | Asynchronous, built-in BFS deep-crawl strategy. |
| **Storage** | Local File System | Simple, zero cloud-lock in, perfect for local dev. |
| **Chunking** | LangChain | `MarkdownHeaderTextSplitter` preserves document structure. |
| **Embeddings**| `all-MiniLM-L6-v2` | Runs locally, fast, zero API costs or rate limits. |
| **Vector DB** | ChromaDB | Lightweight, persists locally without needing a separate Docker container. |
| **LLM** | Groq / Llama 3.3 | Lightning-fast inference with a generous free tier. |
| **Backend** | FastAPI | High performance, native async support. |
| **Frontend** | React + Vite | Fast to build, modular component architecture. |

## 🚀 Getting Started

### Prerequisites
- Python 3.11+
- Node.js (for the frontend)
- [Groq API Key](https://console.groq.com) (Free tier)

### 1. Clone & Configure
```bash
git clone https://github.com/your-username/lumina
cd lumina
cp .env.exemple .env
# Open .env and add your GROQ_API_KEY
```

### 2. Install Backend Dependencies
```bash
pip install -r requirements.txt
```
*Note: Because this project uses `crawl4ai` for web scraping, you must also download the Playwright headless browsers:*
```bash
python -m playwright install
```

### 3. Run the Ingestion Pipeline (One-Time Setup)
This will scrape the GCP docs, chunk them, and build the local ChromaDB vector index.
```bash
python main.py --setup
```
*Note: You will see files populate in the `data/` and `chroma_db/` folders.*

### 4. Start the Application Servers
You need to run the API and Frontend in two separate terminals.

**Terminal 1: Start the FastAPI Backend**
```bash
python -m uvicorn api.main:app --host 0.0.0.0 --port 8000 --reload
```

**Terminal 2: Start the React Frontend**
```bash
cd frontend
npm install
npm run dev
```

## 🧪 How to Test the Project

Once both servers are running, you can test the application in three ways:

### Method 1: Using the UI (Recommended)
1. Open your browser to the local Vite server (usually `http://localhost:5173`).
2. Type a question related to GCP AI/ML services, for example: 
   - *"How does Vertex AI handle model versioning?"*
   - *"What is the difference between Dialogflow CX and ES?"*
3. The UI will display the answer generated by the LLM based on the local documentation chunks.

### Method 2: Using the API directly (Terminal)
You can bypass the frontend and query the FastAPI endpoint directly:
```bash
curl -X POST http://localhost:8000/ask/ \
  -H "Content-Type: application/json" \
  -d '{"question": "How does Vertex AI handle model versioning?"}'
```

### Method 3: Interactive CLI
If you want to test the Python pipeline directly without starting the FastAPI server:
```bash
python main.py
```
This drops you into an interactive terminal prompt where you can ask questions and see the raw pipeline output.
